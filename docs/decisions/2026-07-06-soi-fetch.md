# SOI-fetch — the fetch-on-cadence half of the §4c resolver (M5 build-order step 2)

*Decision record, 2026-07-06. Implements spec `docs/prospector-m5-runner-spec-2026-07-05.md` §9b
(build-order step 2), on top of the M5 runner skeleton (`2026-07-06-m5-runner-skeleton.md`) and the SOI
reader (`2026-07-04-soi-derived-sector-concentration.md`). Folds into a future spec rev when the runner
is complete.*

## What was built (and the scope boundary)

The SOI **reader** (parse a GICS-industry-grouped Schedule of Investments → `{sector: weight}` → route)
was built in M4 and is verified against two real TEKX NPORT-EX fixtures. This slice builds the **fetch
machinery** that decides *which* EDGAR accession, and *which document within it*, carries a fund's
current SOI — the ingest-layer functions the runner's step-3 retry loop will call:

- `SOI_FORMS = ("NPORT-EX", "N-CSR", "N-CSRS")` and `latest_soi(submissions)` in `ingest/edgar.py`.
- `EdgarClient.filing_index(cik, accession)` (the accession's `index.json` manifest) +
  `resolve_soi_document(index)` (the non-primary SOI exhibit within it).
- `resolve_soi_target(cik, client) -> SoiTarget | None`, composing the above into the coordinates the
  runner hands to `sensors/soi.scan`'s `fetch_body` seam.
- **H4** and a parser-docstring correction (below).

**Deliberately OUT of this slice (step 3 / §9d, §9c, §9e):** the runner's per-run enumeration of the
`sectors_unresolved` launches, the retry-until-it-lands schedule, driving `scan()` on cadence, the
`retry_horizon_days` disposition, the mandate frozen-prior invariant, and the shadow clock. Also out:
the identity fixes **I1/B1/B2**, which land between step 2 and live cadence.

## Decisions

### `latest_soi` is form-priority, not newest-by-date (the one real call)

`latest_soi` walks `SOI_FORMS` **in order** and returns the newest filing of the first tier that has one
— NPORT-EX preferred, N-CSR/N-CSRS a deliberate fallback — rather than the newest filing across all
three forms. **Why:** the reader is verified **only** against NPORT-EX (every SOI golden is NPORT-EX);
N-CSR/N-CSRS render the SOI inside a full shareholder report with a materially different structure the
parser has never seen. A newest-by-date rule would silently prefer a fresh N-CSR over a slightly-older
NPORT-EX and route unverified structure into the reader — the exact flag-don't-guess violation the
module is built on. Cost: on a registrant with a stale NPORT-EX and a fresh N-CSR you fetch slightly
older sectors — honest and re-fetched when a newer NPORT-EX lands (§9d). The non-EX **N-PORT** XML
carries no GICS grouping and is **never** in `SOI_FORMS`.

### `resolve_soi_document` refuses to guess

The SOI HTML is a **non-primary** exhibit (NPORT-EX's `primaryDocument` is `primary_doc.xml`, no GICS),
so it is resolved from the accession's `index.json`: keep the `.htm`/`.html` items, drop the
`{acc}-index.htm` cover page and `primary_doc.*`; **exactly one survivor → it; zero or more than one →
`None` (fault)**. A wrong exhibit is a wrong sector set, so ambiguity refuses to guess (mirroring the
anchor-ambiguity discipline in `ingest/soi.py`). `resolve_soi_target` turns a `None` — or any
network/parse error — into a `None` return, mirroring `resolve_ticker`'s countable-failure discipline:
a failure here must never raise up the deferred-pass pipeline. Distinguishing not-yet from fault, and
the retry schedule, are the runner's job in step 3.

### H4 — the plain-REIT alias lives in config, not the frozen table

The SOI parser had no alias for the plain `REAL ESTATE INVESTMENT TRUSTS` header. That header is **not a
GICS industry** — it is DFIN's collapsed rendering of the equity-REIT industry *group* — so it must not
enter the CONTRACT-frozen 74-row `gics_industry_sector` table (`test_soi_config` guards the count, and
the table re-freezes only on a GICS structure revision). It is registered instead in a **new
`gics_industry_alias` config map**, merged by `_build_table` on top of the canonical table without
clobbering any canonical key. Config (not a hardcoded map) keeps the mapping visible, diffable, and
config-honesty-fossiled. Mortgage REITs always carry the explicit `MORTGAGE` prefix (their own
Financials row), so a plain, unprefixed header is equity → **Real Estate** (pre-ratified in the spec
§9b/§9d prereqs). Verified no `_norm` collision with the existing mortgage alias.

The `_build_table` docstring previously claimed the plain header "still rolls up instead of faulting"
via the parenthetical-strip aliasing. **That mechanism is inaccurate** — stripping `(REITs)` from the
mortgage row yields `MORTGAGE REAL ESTATE INVESTMENT TRUSTS`, never the plain form — so the plain header
rolls up **only** via the new explicit alias. The docstring is corrected to describe both alias sources.

## The fixture-strategy correction (adversarial-check finding)

The runner-skeleton decision doc (`2026-07-06-m5-runner-skeleton.md`, the H4 paragraph) said H4 bites
"the real IG-Credit **equity** blocks." **Verified against the fixtures — this is wrong.** In both real
TEKX NPORT-EX filings the plain `REAL ESTATE INVESTMENT TRUSTS — 1.0%` line sits under `CORPORATE BONDS
& NOTES` (a Bloomberg-BICS *bond-issuer* classification, sibling to `PIPELINES`, `LODGING`, etc.), and
the IG-Credit fund is a bond fund with **no `COMMON STOCKS` block at all**. Anchoring it, the parser
returns `reliable=False, reason="COMMON STOCKS block header not found in fund section"` — it faults
before ever reaching the REIT line, because the industry roll-up only runs inside the `COMMON STOCKS`
bracket. So **no real fixture on hand can exercise the H4 gap.**

Consequence: H4 is proven with a **declared-synthetic** fixture (`test_h4_plain_reit_header_faults_
without_the_alias_and_rolls_up_with_it`): the plain header inside a synthetic `COMMON STOCKS` block
faults without the alias (`unknown GICS industry`) and rolls up to Real Estate (and reconciles) with it
— the "test-proves-it-fires" discipline. H4 remains a legitimate **defensive** alias — a plain collapsed
REIT header inside a real *equity* block is a plausible DFIN rendering, and folding the alias in *before*
live fetch widens inputs beyond the two TEKX fixtures is precisely the point — but its appearance in a
real equity block **stays unverified until live cadence surfaces one**. Do not lower any threshold or
invent a real fixture on the strength of the synthetic case (anti-fitting).

## Drop-and-freeze, never conflated (reaffirmed, CONTRACT §9b)

The frozen `.htm` fixtures are dropped once by hand; **fetch code never refreshes them.** All new tests
are offline behind the `fetch_body` / `fixture_fetch` seams (the autouse socket guard fails any real
connection). The `latest_soi`/`resolve_soi_document`/`resolve_soi_target` tests use **declared-synthetic**
submissions + `index.json` dicts (in-band, obviously test-constructed); the end-to-end
`resolve_soi_target` test uses a synthetic manifest whose single exhibit name equals the real frozen
doc basename (`NPORT_J9C7_54705771_0725.htm`) so the coordinates point at a real document — but the
submissions/index responses are **not** recorded-real and never touch the frozen `.htm`.

**Pre-live-cadence follow-up (not a step-2 blocker):** record one real NPORT-EX `index.json` out-of-band
and confirm `resolve_soi_document` yields exactly one candidate against real data (if a filing carries
extra `.htm` exhibits, the refuse-to-guess fault fires — the intended safe behavior, but observe it once).

## Tests (all offline)

- `tests/test_edgar_client.py` — `latest_soi` (priority-tier over a newer lower tier; N-PORT non-EX and
  unknown forms ignored; tier fallthrough; same-day tie; missing columns → None); `filing_index` (URL
  shape, persist-freeze name, 429 retry via `_get`); `resolve_soi_document` (lone exhibit; >1 → None;
  0 → None; index/primary never selected; malformed → None); `resolve_soi_target` (happy path → coords;
  no-SOI → None; ambiguous doc → None; HTTP error → None, never raises).
- `tests/test_soi_parser.py` — the H4 proves-the-gap test; H4 does not perturb the two real TEKX goldens;
  the §9b consolidated-header + `(continued)`-skip regression (`reliable:True` proves both, since a
  non-skipped continuation would double the fund title and fault as ambiguous).
- `tests/test_soi_config.py` — `gics_industry_alias` shape (canonical values; no `_norm` shadow of a
  canonical industry; `_build_table` merges it, and the plain-REIT key exists only with the alias while
  the canonical config stays 74 rows).

## What's deferred to step 3 (§9d)

The runner enumerates `sectors_unresolved` launches from the fold, calls `resolve_soi_target` on the
retry schedule (SOIs post ~quarterly → weekly, not daily), passes `fetch_body=lambda:
client.filing_text(t.cik, t.accession, t.primary_doc)` to `sensors/soi.scan`, reaches back preserving
`detected_at` as T2, and distinguishes not-yet from fault. That is the genuinely-new runner logic, with
§9c (mandate frozen-prior) and §9e (shadow clock).
