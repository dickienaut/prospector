# Tiingo News API as a Discourse-Capture Source for M6: A Decision-Ready Evaluation

## TL;DR
- **Adopt Tiingo News as a supplement and partial replacement, not a full replacement.** It cleanly replaces the *discovery* half of M6 (deterministic search → top URLs), returning ticker- and tag-tagged, frozen-JSON news records with genuinely good small-cap/emerging-name coverage — but it does **not** return full article body text (only a publisher snippet + a link), so if you require frozen full-text you must still fetch the linked URL, reproducing M6's existing scrape-and-freeze step.
- **On the two make-or-break questions:** (1) *Full-text/small-cap coverage* — small-cap/emerging coverage is a strength (70M+ articles, 65,000+ tickers, 120+ providers including non-traditional blogs and trade press), but full-text availability is a **weakness** (snippet only); (2) *Licensing for indefinite raw storage* — Tiingo's API license is explicitly "internal consumption only" and prohibits redistribution, but contains no clause requiring deletion or capping cache duration, so indefinite internal storage appears permissible — this is a reasoned inference, not an explicit grant, so confirm in writing with Tiingo sales before committing.
- **Cost is a non-issue:** the news feed is bundled into the same flat-rate plans you may already hold — per Tiingo's pricing page, "$30/month (or $300/year) for individuals and $50/month (or $499/year) for internal commercial use" — with the important limit that non-institutional plans give only "3 Months of queryable history and all data going forward."

## Key Findings

**1. What the API returns per article — metadata + a snippet, NOT full body.** The `/tiingo/news` endpoint returns JSON objects with these fields only: `id`, `title`, `url`, `description`, `publishedDate`, `crawlDate`, `source` (domain), `tickers[]`, and `tags[]`. There is **no `body` or `content` field.** Although Tiingo's docs label `description` as a "Long-form description of the news story," real API output shows it is a one-sentence-to-lead-paragraph **snippet**, not the article body. A real example from Tiingo's own Python client shows the `description` for a multi-paragraph Quartz article as just "Which new Apple MacBook should you get? Maybe an iPad." (~54 characters). QuantConnect, which hosts the feed, documents the field at the code level as "Sentence summary of article." **Implication:** to freeze the actual discourse text (the article body), you must still fetch the `url` and scrape it — the same operation M6 does today. Tiingo removes the *search* step, not the *fetch* step, if full text is the goal.

**2. Indexing/query model — strong fit for lead baskets.** You can request `GET https://api.tiingo.com/tiingo/news?tickers=aapl,googl` for a comma-separated set of tickers, filter by `tags`, by `source` (publisher domains), and by `startDate`/`endDate`. You can sort by `publishedDate` or `crawlDate`, page with `limit` (default 100, max 1000) and `offset`, and set `onlyWithTickers=true`. This directly supports "give me all news for this lead's tickers since date X." Each record carries both a publish timestamp (usually publisher-reported) and a crawl timestamp (always Tiingo-recorded), which is valuable for your immutable/fossil model: a large gap between the two signals a backfill.

**3. Source coverage and small-cap depth — a genuine strength.** Tiingo aggregates 120+ news providers across 70M+ articles, adding "700,000+ articles added a month" (~8,000–12,000/day), covering 65,000+ equity tickers. Critically for your use case, Tiingo explicitly targets *non-traditional* sources — blogs, tech publications, trade magazines, niche/industry press — and, per its News API page, "it tags based on slang, company mentions, and/or relevant product mentions, which produces a richer feed that helps users discover new sources of alpha." This is close to ideal for corroborating emerging themes among lesser-known names (SMR/nuclear, uranium, AI-infrastructure/power, GLP-1, quantum, bitcoin miners) *before* they are widely packaged. Note one caveat: per QuantConnect's Tiingo News Feed docs, "The data covers 10,000 US Equities, starts in January 2014, and is delivered on a second frequency. This dataset is creating [sic] by Tiingo integrating over 120 different news providers into their platform." That 10,000-ticker figure is narrower than the 65,000-ticker headline — the headline number spans all listing tiers and asset classes, and coverage *depth* on any specific micro-cap will be uneven.

**4. Historical depth / backfill — thin unless you pay up or self-archive.** Per Tiingo's pricing page, "News API allows 3 Months of queryable history and all data going forward. For commercial clients who require more history (up to 15 years available), please contact sales@tiingo.com." So non-institutional plans give only the trailing 3 months of queryable history, plus everything from your subscription start date forward (which you can archive yourself indefinitely). Deep history reaches back further — the News API page states "History: 25+ Years; Data going back from 1995. 70+ million articles," and "For our institutional clients, our real-time news API comes with historical data stretching from the 1990s with a one-year commitment." That deep archive is **institutional-only, requires a one-year commitment**, and is quoted by sales. So Tiingo is excellent for *going-forward* grounding of leads, but weak for *retroactively* grounding existing leads or backtesting unless you buy the institutional history.

**5. API mechanics.** REST base `https://api.tiingo.com/tiingo/news`; auth via `Authorization: Token <key>` header (same token you already use for EOD prices). Rate limits on the Power tier: 10,000 requests/hour, 100,000/day, 40 GB/month bandwidth, unlimited unique symbols; the $50 commercial tier raises these to 20,000/hour, 150,000/day, 100 GB/month. Freshness is real-time ("articles added instantly as discovered"). A nightly bulk-download flat-file mechanism exists but is institutional-only. Pagination via limit/offset as above.

**6. Pricing — bundled, flat-rate, cheap.** The news feed is included in Tiingo's standard plans. Per the pricing page: "It is simply $30/month (or $300/year) for individuals and $50/month (or $499/year) for internal commercial use." Both carry the "internal use only" license and 3-month news history. (Note: some third-party reviews cite a "$10/month Power plan" — that older/web-app figure conflicts with Tiingo's own current API pricing page of $30/month; treat $30 as authoritative.) Extended history (up to 15 years) and any redistribution/display rights are separately quoted by sales. As an existing EOD customer you likely already pay one of these tiers, so **news may be a $0 marginal add** depending on your current plan.

**7. Licensing / storage / redistribution — the deciding factor, and it is favorable-but-not-explicit.** Tiingo's Terms of Use §7.3 ("Use of the Tiingo API") state: **"All data via the API is for internal consumption only… Redistribution is only available upon special request and permission, and comes with additional fees."** The pricing page reinforces: "Internal use means you may only use the data for your own personal use and you may not display or share the data with another person or organization." §1 grants "a limited license to reproduce portions of Company Properties for the sole purpose of using the Services for your personal or internal business purposes," and §1.4 broadly prohibits licensing, selling, redistributing, or "host[ing]" the data to others, and prohibits scraping *Tiingo's own website* (distinct from using the API). **What the ToS does NOT contain:** any clause requiring deletion of API data, any maximum cache/retention duration, or any prohibition on persistent local storage for internal use. Indeed, Tiingo's own marketing tells non-institutional clients they get "the past 3 months of data with real-time updates so you can **keep an extensive database internally**" — an explicit invitation to build a permanent internal store. **Reasoned conclusion:** an append-only, never-redistributed, internal-only fossil archive is consistent with the license. But because the ToS never affirmatively says "you may retain indefinitely," and because news is aggregated third-party publisher content, this is an inference — get written confirmation from sales before treating it as settled.

## Details

### How this maps onto M6's two hard architectural rules
- **Rule 1 — no LLM-generated prose persisted.** Fully satisfied. Tiingo's `description`/`title`/`tags` are algorithmically *tagged* but the text itself is third-party, publisher-authored content (or Tiingo's crawl of it), not LLM-generated prose. Storing the raw JSON alongside your own deterministic query parameters honors the rule cleanly. (One nuance: `tags` and `tickers` are Tiingo's algorithmic classifications, but they are structured metadata, not LLM prose — fine to persist.)
- **Rule 2 — everything storable as a frozen raw payload.** Fully satisfied and arguably *better* than the status quo: the API returns a compact, well-structured JSON block per article that is trivially frozen verbatim, versus M6's current freezing of messy raw HTML/page text.

### The full-text problem, stated precisely
M6 today freezes "raw search-result blocks plus the fetched page text." Tiingo replaces the search-result blocks with something far cleaner (ticker-tagged JSON), but the "fetched page text" (the article body) is **not** in the Tiingo payload. You therefore have three design options:
1. **Snippet-only fossils:** freeze just the Tiingo JSON (title + snippet + tags + URL). Lowest legal risk (you store minimal third-party text), lowest engineering effort, but you lose full-body discourse. For *corroboration of theme formation* — your stated highest-value use — headline + snippet + tag co-occurrence across many niche sources is often sufficient signal.
2. **Snippet + selective fetch:** use Tiingo as the discovery/index layer, then fetch-and-freeze the body only for a budgeted subset of URLs (e.g., first N per lead per week). This preserves M6's full-text capability while getting Tiingo's superior discovery and dropping the general web-search API entirely.
3. **Hybrid:** keep Tiingo for tagged-ticker discovery and keep the existing search API only for query patterns Tiingo can't express (pure thematic keyword searches not tied to a ticker).

### Ingesting a self-managed indefinite archive around the 3-month window
Because queryable history is capped at 3 months but you may keep everything going forward, the correct pattern is a **daily incremental pull** (sort by `crawlDate`, page through everything since your last high-water mark) written straight to the fossil store. This turns Tiingo's short server-side history into an unbounded client-side archive — exactly M6's model — and sidesteps the institutional history upsell for all go-forward analysis.

### Comparative context (secondary)
On the two axes that matter — (a) small-cap coverage + full-text, and (b) storage/redistribution licensing + price:

- **Benzinga (via Massive/Polygon):** The strongest on full text — the feed is explicitly designed to be "fully embeddable… the entire headline, body, and picture," with a `body` field and history to 2009. But it is Benzinga's own editorial (130–160 full articles/day plus 600–900 headlines), so it is US-focused, event-driven (upgrades, price targets, M&A), and **thin on the niche/blog/trade-press sources** that surface emerging small-cap themes. Priced for platforms/enterprise (quote-based), materially above Tiingo. Its license is oriented toward *display/redistribution on your platform* — more than you need, and priced accordingly.
- **Polygon.io / Massive news:** Returns summary + `article_url` + ticker tags + sentiment "insights," not third-party full bodies (except Benzinga content via partnership). Similar snippet-plus-link shape to Tiingo; strong developer ergonomics; US-centric.
- **Marketaux:** Snippet + per-entity "highlights" + sentiment across ~5,000 sources / 200,000+ entities, 30+ languages. Not full body. Good breadth, free tier (100 req/day). Terms are clearer on real-time use but softer on archive redistribution — archival storage rights are not clearly granted.
- **EODHD:** Notably, its `/news` endpoint returns a `content` field that carries **substantially fuller article text** than a one-line snippet (its own examples show multi-sentence content), ticker-tagged with sentiment, from "dozens" of sources, starting at $19.99/month. Commercial/internal-use plans restrict sharing outside your company (same internal-use model as Tiingo). Fewer sources than Tiingo and less emphasis on niche/blog coverage, but if fuller text in the payload matters, EODHD is the closest cheap alternative — **worth a direct side-by-side test against Tiingo on your specific lead universes.**
- **Financial Modeling Prep:** Headline + snippet + URL + ticker + sentiment, cheap, real-time and historical, but general-aggregator depth; snippet-only like Tiingo.
- **NewsAPI.org:** General-purpose (not finance-tagged), snippet-only, and its developer terms are restrictive on retention/commercial use — a poor fit for a finance-lead, indefinite-archive design. Not recommended here.

**Net comparative read:** Tiingo is best-in-class on *small-cap/emerging-name discovery* and on *clean, frozen, internal-use-licensed payloads at a trivial price*, and you already have an account and token. It is *not* best-in-class on *full-text-in-payload* — Benzinga (full editorial body) and EODHD (fuller `content` field) beat it there, at the cost of niche coverage (Benzinga) or breadth (EODHD).

## Recommendations

**Stage 1 — Pilot (this month, ~$0 marginal cost).** Confirm your current plan includes news API access (Power/Commercial both do). Wire a read-only daily incremental pull (`sortBy=crawlDate`, `onlyWithTickers` optional, `tickers=` per lead basket) into a throwaway store. Run it for 2–4 weeks against your live lead universes (nuclear/SMR, uranium, AI-power, GLP-1, quantum, bitcoin miners). **Benchmark that decides Stage 2:** for your *lowest-profile* names, does Tiingo surface ≥3–5 distinct, relevant, correctly-tagged sources per emerging theme per week that your current search-API pipeline misses or finds late? If yes, proceed.

**Stage 2 — Adopt as the discovery/index layer.** Replace M6's deterministic-search-query step with Tiingo ticker/tag pulls, and freeze the returned JSON verbatim as fossil records (Design Option 1). Keep `id` as the dedupe key and `crawlDate` as the append high-water mark. This satisfies both architectural rules and eliminates the general web-search API dependency for ticker-anchored leads.

**Stage 3 — Decide the full-text question deliberately.** If snippet+tags prove sufficient for corroboration (likely, given your stated goal is *theme detection among niche names*, not deep reading), stop here. If you need frozen bodies, add a **budgeted** URL-fetch on top of Tiingo (Design Option 2), preserving your existing monthly spend cap. Before scaling any body-storage, run a quick EODHD `content`-field trial to see whether a provider that ships fuller text in-payload lets you drop the scrape step entirely.

**Before committing to indefinite storage, do this one thing:** email Tiingo sales (sales@tiingo.com) and get written confirmation that an internal-only, never-redistributed, indefinitely-retained archive of API-delivered news JSON is permitted under your plan. The ToS supports this reading but does not state it explicitly.

**Thresholds that would change the recommendation:**
- If Tiingo's niche-name coverage fails the Stage 1 benchmark → keep the search-API pipeline and treat Tiingo as an add-on rather than a replacement.
- If you decide frozen full-text bodies are mandatory → EODHD (fuller `content`) or Benzinga (full editorial body, if US-large/mid-cap event coverage suffices) become serious contenders over Tiingo.
- If sales confirms storage is *not* permitted indefinitely → fall back to snippet-only records with a short TTL, or choose a provider with explicit archival rights.

## Caveats
- **The "Long-form description" label is misleading.** Tiingo's docs oversell the `description` field; ground-truth API output and QuantConnect's schema ("Sentence summary of article") confirm it is a snippet. Do not architect assuming you get bodies.
- **Indefinite-storage permission is inferred, not explicit.** The license is internal-use-only and silent on retention duration and deletion; this is favorable but unconfirmed. Treat the sales-email confirmation as a gating step.
- **History is short unless institutional.** 3-month queryable window on non-institutional plans; deep history is a one-year institutional commitment. Retroactive grounding of existing leads is limited without it.
- **Coverage depth on any specific micro-cap is uneven.** The 65,000-ticker / 70M-article headlines describe the whole corpus; the QuantConnect-hosted variant citing 10,000 US equities from 2014 suggests real depth is concentrated in more-covered names. Validate on *your* names in the pilot rather than trusting headline counts.
- **Pricing figures conflict across sources** ($10 vs $30 Power); Tiingo's own current API pricing page ($30/mo individual, $50/mo commercial) is treated as authoritative here, but verify against your account's live pricing.
- **Tags/tickers are algorithmic.** Tiingo's tagging is proprietary and occasionally noisy; for an immutable fossil store this is fine (you freeze what you received), but downstream v2 interpretation should treat tags as Tiingo's classification, not ground truth.
